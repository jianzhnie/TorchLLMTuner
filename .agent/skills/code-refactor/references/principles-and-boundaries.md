# 重构原则与职责边界

## 职责边界（不可逾越）

各层职责必须保持并强化：`config/` 定义配置，`datasets/` 构建数据管线，
`models/` 模型行为，`parallel/` 应用 FSDP/TP/PP/CP/EP，`memory/` 显存优化，
`components/` 可复用训练服务，`trainer/` 编排执行。并行族以其同名文件作为
公共入口（如 `parallel/tensor_parallel/tensor_parallel.py`）。重构是让归属
错误的代码回到正确的层，而不是重新分层。

## 重构原则（按优先级）

1. **行为不变**：不改变训练语义、数值结果、公共 API 契约。任何会改变行为
   的"优化"单独列出，不混入重构。
2. **删除冗余**：移除死代码、无人调用的函数/类、被处处绕过的包装层。
3. **消除浅包装**：合并只有单一调用方且不承载独立契约的封装类/函数；不为
   统一外观保留无消费者的抽象。保留具有独立责任的构件——判断依据是职责
   而非文件大小。
4. **归位**：放错层的代码移回职责所在层；消除循环依赖；导入一律从定义
   叶子模块导入，`__init__.py` 只暴露有意的公共 API。
5. **简化**：能用直白语句表达的不用花哨抽象；重复逻辑提取为单一实现；
   配置默认值、校验逻辑只在一处定义。
6. **命名准确**：名称表达职责（如 `loader_builder`、`state_dict_adapter`）；
   不为统一外观重命名已经准确的公共 API。重命名后同步更新实现导入、公共
   导出、测试、示例和文档，并全局搜索旧引用确认清零。
7. **高效**：移除明显的热路径浪费（重复计算、不必要的拷贝、可缓存的反复
   构造），但不引入有行为风险的微优化。

## 文档同步

变更后清扫注释和 docstring，使其与新行为一致；变更若触及 AGENTS.md 描述的
结构，同步更新 AGENTS.md。
